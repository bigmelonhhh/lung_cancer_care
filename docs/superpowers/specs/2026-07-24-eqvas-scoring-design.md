# EQVAS 数字填空与 EQ-5D-5L 健康效用指数设计

## 目标

完善随访问卷的 `TEXT（问答/填空）` 答题链路，并为编码以
`Q_EQVAS` 开头的问卷提供中国大陆 EQ-5D-5L 健康效用指数计算。

已锁定的 EQVAS 配置为固定六题：

1. 行动能力（单选，选项 `value=1..5`）
2. 自我照顾（单选，选项 `value=1..5`）
3. 日常活动（单选，选项 `value=1..5`）
4. 疼痛/不适（单选，选项 `value=1..5`）
5. 焦虑/抑郁（单选，选项 `value=1..5`）
6. EQ-VAS 自评（TEXT，患者填写 `1..100` 整数）

当前数据库中的 `Q_EQVAS001`、题目 74 至 79 已符合该结构。

## 答题与接口

患者答题页面按问卷编码和题型渲染：

- 普通问卷的 TEXT 使用普通文本输入框，最多 2000 字，不参与 `SUM`。
- `Q_EQVAS*` 的第六道 TEXT 使用数字输入框，仅接受 ASCII 整数
  `1..100`，禁止小数、符号、科学计数法、空格和中文数字。
- 单选和多选保持当前控件与答案结构。
- 所有题型统一遵循题目的 `is_required` 配置。

提交接口保持 `POST /p/api/survey/submit/`，答案支持两种结构：

```json
[
  {"option_id": 301},
  {"question_id": 79, "value_text": "78"}
]
```

前后端都进行输入校验，后端是最终可信边界。TEXT 答案落库为
`question=<题目>`、`option=NULL`、`value_text=<输入内容>`。EQ-VAS 的
`1..100` 只作为答题详情数据保存，不参与健康效用指数。

## 计分架构

新增独立的问卷计分模块，提交服务负责答案校验、事务编排和落库，
计分模块负责选择计算器：

- 普通问卷继续使用现有 `SUM`，累加选中选项的 `score`。
- 编码满足 `questionnaire.code.upper().startswith("Q_EQVAS")` 时，
  使用专用 `Eq5d5lChinaCalculator`。

EQVAS 计算器只依赖固定题序和选项 `value`，不依赖题目文案、问卷名称
或运营配置的 `score`。前五题依次解释为 MO、SC、UA、PD、AD，并使用
以下中国大陆价值集扣减系数：

| 维度 | 1级 | 2级 | 3级 | 4级 | 5级 |
|---|---:|---:|---:|---:|---:|
| 行动能力 MO | 0 | 0.066 | 0.158 | 0.287 | 0.345 |
| 自我照顾 SC | 0 | 0.048 | 0.116 | 0.210 | 0.253 |
| 日常活动 UA | 0 | 0.045 | 0.107 | 0.194 | 0.233 |
| 疼痛/不适 PD | 0 | 0.058 | 0.138 | 0.252 | 0.302 |
| 焦虑/抑郁 AD | 0 | 0.049 | 0.118 | 0.215 | 0.258 |

计算公式：

```text
健康效用指数 = 1 - MO扣减 - SC扣减 - UA扣减 - PD扣减 - AD扣减
```

全程使用 `Decimal`，只在最终结果执行一次
`ROUND_HALF_UP` 两位小数舍入。结果不截断到 `0..1`，负健康效用值允许
保存。例如：

- `11111 -> 1.00`
- `21324 -> 0.554 -> 0.55`
- `55555 -> -0.391 -> -0.39`

最终健康效用指数写入：

- `QuestionnaireSubmission.total_score`
- 对应问卷 `HealthMetric.value_main`

现有字段已支持两位小数，无需模型变更或 migration。

## 配置校验与事务

`Q_EQVAS*` 提交前必须满足：

- 恰好六道题，按 `seq` 和主键稳定排序。
- 前五题为单选题，且每题恰好提交一个选项。
- 前五题提交选项属于对应题目，选项 `value` 为整数 `1..5`。
- 第六题为 TEXT，必填时答案为 `1..100` 整数。
- 不允许引用其他问卷的题目或选项。

配置或答案不符合时抛出可消费的 `ValidationError`。整个提交事务回滚，
不创建提交、答案、健康指标，不完成每日任务，也不失效首页完成状态。

## 展示

- 患者健康档案卡片和记录列表显示健康效用指数。
- 医生患者指标趋势显示健康效用指数，系列名称使用“健康效用指数”。
- EQVAS 图表纵轴固定为 `-0.40..1.00`，不使用普通选项分推导范围。
- 管理统计仍统计问卷提交次数，不改变现有口径。
- 患者端和医生端答题详情展示六道题答案，第六题显示 EQ-VAS 原始整数。
- 不新增 EQVAS 分级、异常次数或预警规则。

## 测试与验收

服务测试覆盖：

- `11111`、`21324`、`55555` 的健康效用指数和舍入结果。
- EQ-VAS 边界值 `1`、`100` 成功。
- `0`、`101`、`1.5`、`1e2`、符号、空白和中文数字被拒绝。
- 固定六题结构、题型、选项归属、选项 `value` 和必填完整性校验。
- 改变题目或选项显示文案不影响计算。
- 普通 `SUM` 单选、多选行为不变，普通 TEXT 保存但不计分。
- 任一校验失败时事务没有部分数据。

页面与集成测试覆盖：

- `Q_EQVAS*` TEXT 渲染数字输入框并生成
  `question_id + value_text` 请求。
- 普通 TEXT 仍渲染文本输入框。
- 患者答题成功后今日计划刷新为完成。
- 患者和医生详情显示 EQ-VAS 原始值。
- 患者健康档案及医生趋势只展示健康效用指数，图表范围正确。

最终验证运行受影响测试、浏览器测试、Django 全量测试、
`python manage.py check` 和 `git diff --check`。
