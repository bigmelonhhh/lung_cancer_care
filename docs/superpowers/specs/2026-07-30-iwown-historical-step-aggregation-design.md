# IWOWN 历史步数累计设计

## 目标

修复 IWOWN 新设备只上传 `0x80` 历史健康数据时步数无法入库的问题，并继续让 `HealthMetric` 只保存患者每天的累计步数。

本次改动不新增字段、不修改数据库表、不生成 migration，也不保存分钟级步数明细。

## 已确认的协议语义

IWOWN 的两类步数来源语义不同：

- `0x0A`：设备当天的累计步数、距离和卡路里；其中步数可直接作为当天累计值。
- `0x80 -> HisData.health -> pedo_data`：按采样时段上报的步数、距离和卡路里；其中 `step` 是该时段的增量。

当前实现只解析 `0x0A` 步数，遗漏了 `0x80` 健康数据中的 `pedo_data`，所以只上传历史数据的新设备不会产生步数指标。

## 设计原则

### 1. 区分累计值和增量值

在运行时的 `DeviceMetricReading` 中增加一个不落库的步数聚合语义：

- `cumulative`：当天累计值。
- `increment`：时段增量值。
- 未设置：沿用现有设备适配器行为。

IWOWN 适配器按以下方式生成读数：

- `0x0A` 步数标记为 `cumulative`。
- `0x80` 的 `pedo_data.step` 标记为 `increment`。

该字段只用于服务层选择写入方式，不改变任何数据库模型。HRT 等其他设备来源保持现有逻辑。

### 2. 只保留一条每日累计步数

`0x80` 增量步数进入现有设备指标入库事务后：

1. 按患者时区定位读数所属日期。
2. 锁定并读取当天已有的步数 `HealthMetric`。
3. 没有记录时以本次增量创建记录；已有记录时把增量加到现有累计值上。
4. 当天始终只保留一条累计步数记录，不保存分钟级明细。
5. `measured_at` 只向后更新，不因乱序数据倒退。

步数必须为非负数。零步数允许正常处理和去重，但不会降低已有累计值。

### 3. 使用现有回执表实现幂等

不新建去重表，复用 `DeviceMetricReceipt`：

- `0x80` 继续使用数据包中已有的稳定事件标识。相同数据包重试时，先命中回执，不再重复累加。
- 增量写入与回执创建位于同一数据库事务内；写入失败时不会留下成功回执。
- 回执只保存事件键，不保存分钟级步数值。

这会让步数也产生内部回执记录，但不会增加新的业务数据表或用户可见的分钟明细。

### 4. 处理 0x0A 与 0x80 的重叠

`0x0A` 是设备提供的当天权威累计值，仍按现有“累计值不回退”规则写入：

- 新累计值大于等于当前值时更新。
- 新累计值小于当前值时保留当前值。
- 每次合法的 `0x0A` 读数都参与比较，不能因为当天已有标记就跳过，否则后续更大的累计值无法更新。

系统在收到当天合法的 `0x0A` 后，使用现有 `DeviceMetricReceipt` 写入一个确定性的日标记，例如：

`iwown:steps:cumulative:2026-07-30`

该标记表示当天已经出现权威累计流，而不是表示某一个 `0x0A` 数据包已处理。即使本次 `0x0A` 没有提高当前累计值，也要建立日标记。

同一天后续到达的 `0x80` 增量不再累加，避免累计数据和历史分段数据重复计算。具体顺序如下：

- 只有 `0x80`：各时段增量持续累加为当天累计值。
- 多次收到相同 `0x80`：回执去重，只累加一次。
- 先收到 `0x80`，后收到 `0x0A`：先累加历史分段；`0x0A` 再按“不回退”规则校正，并建立日标记。
- 先收到 `0x0A`，后收到 `0x80`：建立日标记后忽略当天后续 `0x80` 增量。
- 建立日标记后又收到更大的 `0x0A`：仍允许更新当天累计值。

日期计算沿用 `HealthMetric` 当前的本地日期边界，日标记与指标归属日期保持一致。

## 解析范围

本次只补充：

`0x80 -> data_type 0 -> health field 3 -> pedo_data -> step field 4`

距离和卡路里不在本次范围内。其他 `0x80` 历史健康指标、现有 `0x0A` 解析和 HRT 设备逻辑保持不变。

## 错误与兼容处理

- 缺失或损坏的 `pedo_data` 不生成步数读数，不影响同包其他指标。
- 无效的负步数不写入累计值，并记录可定位设备和事件的异常上下文。
- 设备未绑定、设备或厂商停用等现有校验继续生效。
- 保持现有回调响应方式，避免设备因为业务数据异常持续重试整个请求。

## 测试范围

实现时先补失败测试，再修改业务代码，至少覆盖：

1. 适配器能从官方字段结构的 `0x80 pedo_data` 解析步数，并标记为增量。
2. 同一天两个不同 `0x80` 增量合并成一条累计步数指标。
3. 相同 `0x80` 数据包重试不会重复累加。
4. 当天已有 `0x0A` 日标记时，后续 `0x80` 不再累加。
5. 先 `0x80` 后 `0x0A` 时按“不回退”规则校正，并阻止再来的 `0x80`。
6. 日标记存在时，更大的后续 `0x0A` 仍能更新累计值。
7. 现有 IWOWN `0x0A`、其他历史指标和 HRT 测试保持通过。

## 非目标

- 不补跑已经错过的生产回调数据。
- 不增加分钟级步数查询或展示。
- 不改造距离、卡路里指标。
- 不修改数据库 Schema 或生成 migration。
- 不调用设备厂商接口触发历史数据重传。
