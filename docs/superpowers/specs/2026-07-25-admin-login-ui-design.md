# Django Admin 登录页 UI 改造设计

**日期**：2026-07-25

**范围**：仅限 `/admin/login/`

**状态**：视觉方案已确认

## 1. 目标

为慢病康复管理系统的 Django Admin 登录页建立更专业、可信、克制的视觉形象，服务医务工作人员和企业运营管理人员。

本次只改变登录页的模板结构与样式，不改变认证、权限、表单校验、错误消息、CSRF 防护或登录后跳转逻辑。

## 2. 视觉方向

采用已确认的 **A 方案：医疗协作中枢**。

- 整体使用左右分栏布局。
- 左侧为深青绿色品牌区，强调医疗可信度和慢病管理场景。
- 右侧为暖白色登录区，保持表单清晰、安静且易操作。
- 设计风格专业、稳重、有医疗温度，不使用过度装饰或与医疗场景无关的视觉元素。
- 桌面端保留双栏结构；窄屏设备自动切换为上下布局。

## 3. 页面内容

### 3.1 左侧品牌区

品牌区只保留以下内容，不增加英文眉题、功能标签或业务统计：

- 图标：复用 `static/logo-192.png`。
- 主标题分为两行：
  - `基于AI与智能硬件的`
  - `慢病数字化康复管理`
- 说明文案：
  - `连接患者与医生的数字化桥梁。通过医疗级物联网硬件实现连续体征监测，将院外康复由“盲盒”状态转为精细化管理。`

### 3.2 右侧登录区

- 品牌名称：`慢病康复管理系统`。
- 登录标题：`欢迎回来`。
- 登录说明：`登录慢病康复管理系统后台`。
- 表单继续使用 Django Admin 提供的原始字段、字段错误、非字段错误和提交按钮。
- 底部辅助提示：`仅限已授权的医务及运营管理人员使用`。

## 4. 技术实现边界

新增项目级 `templates/admin/login.html` 覆盖 Django 自带登录模板，并通过 Django 模板继承保留 Admin 的上下文和表单行为。

样式采用登录模板专属 CSS，不修改 Python 认证代码，不引入新的前端依赖，也不影响登录后的 Admin 首页、列表页、详情页或其他业务端页面。

必须保留以下 Django Admin 行为：

- 表单提交地址和请求方法。
- `{% csrf_token %}`。
- `username` 与 `password` 原始字段对象及其属性。
- 字段错误与非字段错误输出。
- 已登录但无权限时的提示。
- `next` 隐藏字段和登录成功后的目标跳转。
- 当前 `base_site.html` 提供的页面标题与 favicon。

## 5. 响应式与无障碍

- 桌面宽屏使用左右双栏，登录表单宽度保持在易阅读范围内。
- 平板和手机切换为上下布局，品牌区缩短，表单保持完整可操作。
- 保留真实 `<label>` 与输入框关联。
- 提供明显的键盘焦点状态。
- 错误提示使用文字、边框和颜色共同表达，不只依赖颜色。
- 避免无意义动画；如提供进入动效，需兼容 `prefers-reduced-motion`。

## 6. 错误状态

错误内容由 Django 原样提供，只调整视觉呈现。

- 已登录但无访问权限的提示需保留完整语义。
- 用户名或密码错误时继续显示 Django Admin 的非字段错误。
- 单字段错误在对应输入项附近显示。
- 不在前端改写或吞掉任何后端错误。

## 7. 验证标准

### 自动化验证

- 登录页使用项目覆盖模板。
- 页面引用 `static/logo-192.png`。
- 页面包含已确认的主标题和说明文案。
- 页面保留 CSRF、用户名、密码、提交按钮和 `next` 字段。
- 当前 favicon 测试继续通过。
- Django system check 通过。

### 浏览器验证

- 访问 `/admin/login/?next=/admin/` 时显示新的双栏登录页。
- 正常桌面宽度下布局、字体、间距和颜色符合确认稿。
- 窄屏下没有水平滚动，表单字段和按钮可正常操作。
- 无权限登录提示和错误登录提示均可见且不破坏布局。
- 成功登录仍跳转至原有 `next` 目标。

## 8. 明确不做

- 不修改登录后的 Django Admin 视觉。
- 不修改用户模型、认证后端、权限规则或登录业务逻辑。
- 不新增或修改数据库 migration。
- 不替换 `static/logo-192.png` 文件内容。
- 不引入第三方 UI 框架、字体服务或 JavaScript 交互库。
